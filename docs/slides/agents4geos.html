What it is & why it exists

The problem. A GEOS simulation is a 200–500 line XML deck: cross-referenced parameters across solvers, constitutive models, mesh, boundary conditions, and outputs. Easy to get subtly wrong.

The idea. Describe the simulation in English; a team of agents — each specialized in schema, fluids, meshing, validation, or post-processing — collaborates to produce a deck that is schema-valid, cross-referenced, and physically sane.

Grounded, not guessed

Outputs are backed by real physics computations (PVT via pyResToolbox, mesh/VTK via PyVista) and by domain knowledge audited from 200+ official GEOS input files — not free-form model recall.

Five kinds of components

Tools do work · knowledge encodes expertise · agents decide what work to do.

Agent

A skill file giving Claude a role, workflow & authority. Has a tier, a tool set, and I/O contracts.

Tool

A stateless @mcp.tool. Inputs → outputs. No memory, no decisions, no awareness of peers.

Knowledge

Static Python data: field names, constitutive assemblies, cross-refs, sanity rules. Read by tools.

State

The DocumentStore — in-memory doc_id → XML, shared across tool calls in a session.

Hook

Shell script Claude Code fires after tool use — e.g. auto-validate XML, auto-screenshot VTK. Reacts, never decides.

Agents come in two forms: prompt-overlay skills (skills/geos:*.md, run in the main conversation) and real subagents (.claude/agents/*.md, dispatched with their own context & model).

Agents & model routing

Each agent declares a tier; the orchestrator picks the cheapest model that handles it reliably.

Tier 1 · Haiku Retrieval — lookup, extraction, formatting. e.g. geos:schema, geos:inspect, geos:curate-errors
Tier 2 · Sonnet Synthesis — assembly, validation, computation. e.g. geos:edit, geos:validate, geos-mesh, geos-fluids, geos-postprocess
Tier 3 · Opus Planning — multi-step reasoning, user dialogue, design. e.g. geos (orchestrator), geos:run, geos-reviewer

geos is the only agent that talks to the user; everyone else reports back to it. Tiers are recommendations — as models improve, an agent can move down a tier without changing its definition.
